# Лабораторная работа №6. Современные возможности PostgreSQL и оптимизация запросов

## 1. Использование типа JSONB
**Назначение:** Добавление и заполнение столбца для слабоструктурированных данных (характеристик товаров).
**Пояснение:** JSONB позволяет хранить разные атрибуты для разных категорий (цвет/память для телефонов, автор/страницы для книг) в одной колонке, не создавая десятки лишних столбцов с NULL.

## 2. Запросы к JSONB
**Назначение:** Извлечение данных и поиск по вхождению.
**Пояснение:** Оператор `->>` извлекает значение в виде текста. Оператор `@>` проверяет наличие заданного фрагмента JSON внутри документа.

## 3. Анализ планов: EXPLAIN ANALYZE (ДО индексов)
**Назначение:** Замер времени выполнения запроса без индексов.
**Результат:** Тип сканирования — `Seq Scan` (последовательное сканирование). Время выполнения: [Вставь время, например, 0.150 ms].

## 4. Добавление B-tree индекса
**Назначение:** Ускорение поиска по диапазону цен.
**Результат после индекса:** Тип сканирования изменился на `Index Scan` (или `Bitmap Index Scan`). Время выполнения уменьшилось: [Вставь новое время, например, 0.050 ms].
**Пояснение:** B-tree индекс позволяет быстро находить нужные значения без полного перебора таблицы.

## 5. GIN-индекс для JSONB
**Назначение:** Ускорение поиска по вхождению в JSONB (`@>`).
**Результат:** При выполнении запроса с `@>` план показывает использование `Bitmap Index Scan on idx_products_attributes`.
**Пояснение:** GIN-индекс эффективно работает с составными структурами (JSONB, массивы), в отличие от обычного B-tree.

## 6. Цена индексов (вставка данных)
**Назначение:** Демонстрация того, что индексы замедляют операции записи.
**Результат:** 
- Массовая вставка 5000 строк с индексами заняла: [Вставь время, например, 150 ms].
- Массовая вставка 5000 строк без индексов заняла: [Вставь время, например, 80 ms].
**Пояснение:** При наличии индексов СУБД тратит дополнительное время на обновление структуры индекса при каждой вставке, что замедляет операции записи. Поэтому индексы создают только под конкретные частые запросы.

## 7. Обоснование выбора индексов
**Вывод:** 
Индекс `idx_products_price` (B-tree) создан, так как запросы часто фильтруют товары по цене (диапазоны). 
Индекс `idx_products_attributes` (GIN) необходим для эффективного поиска по JSONB-полям. Создание этих индексов оправдано ускорением выборки данных.
