# Лабораторная работа №1. Проектирование базы данных маркетплейса

## 1. Анализ предметной области и бизнес-правила
1. Пользователь может быть покупателем, а также владельцем магазина-продавца.
2. Продавец размещает множество товаров.
3. Товар принадлежит ровно одному продавцу и относится к одной категории.
4. Категория может иметь родительскую категорию (иерархия).
5. Заказ оформляется одним пользователем и содержит одну или несколько позиций.
6. Один товар может входить в множество заказов (связь M:N через order_items).
7. Отзыв оставляется конкретным пользователем к конкретному товару.

## 3. Нормализация до 3НФ

### Пример аномалии до нормализации:
Представим, что мы хранили бы данные о продавце прямо в таблице товаров (`products`): `id`, `title`, `price`, `seller_name`, `seller_email`.
*   **Аномалия обновления:** Если продавец сменит email, нам пришлось бы обновлять его во всех товарах этого продавца (тысячи строк). Если где-то пропустить — данные станут несогласованными.
*   **Аномалия вставки:** Нельзя добавить нового продавца, пока он не выставил хотя бы один товар.

### Как устранено (Приведение к 3НФ):
Мы вынесли данные о продавцах в отдельную таблицу `sellers`. В таблице `products` оставили только `seller_id` (внешний ключ).
*   **1НФ:** Все значения атомарны (нет списков в одной ячейке).
*   **2НФ:** Все неключевые атрибуты зависят от всего первичного ключа (в составных ключах, например `order_items`, `quantity` и `unit_price` зависят от `(order_id, product_id)`).
*   **3НФ:** Устранены транзитивные зависимости (например, `seller_name` больше не зависит от `product_id`, а зависит только от `seller_id` в своей таблице).

## 4. Выбор ключей
Для всех таблиц выбраны **суррогатные ключи** (`BIGINT GENERATED ALWAYS AS IDENTITY`). 
*   *Обоснование:* Они стабильны, компактны, не меняются со временем и не зависят от бизнес-правил. Естественные ключи (например, email пользователя) могут измениться, что привело бы к каскадному обновлению всех связанных таблиц.

## 5. Словарь данных (Пример)

| Таблица | Столбец | Тип данных | Ограничения | Назначение |
| :--- | :--- | :--- | :--- | :--- |

| | price | NUMERIC(12,2) | CHECK (price > 0) | Цена товара |
| **orders** | id | BIGINT | PK, Identity | Идентификатор заказа |
| | user_id | BIGINT | FK, NOT NULL | Покупатель |
| | status | VARCHAR(20) | CHECK (...) | Статус заказа |
| | total_amount | NUMERIC(12,2) | CHECK (>= 0) | Итоговая сумма |
